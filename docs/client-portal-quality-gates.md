# Стандарт качества клиентского кабинета

Этот документ — обязательный внутренний промпт для любых изменений в `/portal/*`.

## Промпт визуального исполнителя

Ты проектируешь мобильный кабинет клиента boutique fitness-студии Balance. Цель — не декоративность, а спокойный, быстрый и понятный интерфейс. Используй фирменную палитру: тёплый cream-фон, белые поверхности, тёмный sage для основных действий, графитовый текст и приглушённые статусные цвета. Не используй ярко-синие CTA, тяжёлые тени, случайные градиенты и разные стили кнопок.

Перед сдачей каждого экрана проверь ширины 320, 375, 390, 430 и 768 px. На мобильном никакой текст, счётчик или кнопка не выходит за карточку, нет горизонтальной прокрутки. Длинное название занимает максимум две строки, имя тренера — одну строку в формате «Имя Ф.». Время и количество свободных мест остаются неделимыми элементами одной строки. На ширинах до 479 px действие располагается отдельной полноширинной строкой. Все состояния действия имеют одинаковые высоту 44 px, ширину и радиус: «Записаться», «Отменить запись», «Отмена закрыта», «Мест нет», «Запись закрыта», «Занятие отменено».

Не принимай изменение по одному красивому скриншоту. Проверь длинное направление, длинное имя, 0/1/10/100 свободных мест, загрузку, записанного клиента, закрытую отмену, заполненное и отменённое занятие. Цвет всегда дублируется текстом. Последняя карточка не перекрывается нижней навигацией и safe-area Safari.

## Промпт бизнес-логики и контролёра

Ты проверяешь полный путь «интерфейс → API → база → повторное отображение». Не изменяй остаток абонемента арифметикой вида `+1/-1`; всегда пересчитывай его идемпотентно из уникальных записей, связанных с конкретным абонементом.

Статусы расходуют занятие только так:

- `booked` — место зарезервировано, занятие не списано;
- `completed` — занятие списано;
- `absent` — занятие списано;
- `late_cancel` — занятие списано;
- `cancelled` — занятие не списано;
- `transferred` — исходная запись не списывается сама по себе.

Остаток никогда не может быть меньше 0 или больше исходного количества. Повторное сохранение того же статуса не меняет остаток. Переходы `booked → completed/absent/late_cancel` списывают ровно один раз; обратный переход в `cancelled` возвращает результат пересчётом, но не превышает номинал. Будущая запись не уменьшает остаток. Срок действия включителен и считается отдельно от остатка.

Перед сдачей обязательны: unit-тесты переходов статусов, production-сборка, проверка реального мобильного интерфейса, контроль API-ответа и данных до/после. Контролёр отклоняет работу, если проверена только сборка либо только внешний вид.
